# Licence proofs

SPEC-81 §4.3 uses this folder for licence texts, permitted receipts and written permissions. The register is [LICENSES.md](../LICENSES.md), with one exact asset path per row. An empty proof folder or a planned manifest row never establishes rights.

Use readable ASCII filenames without spaces, grouped by source/family when one licence covers several files. Keep the original licence/permission text, the originating source URL, the asset/version identification and the date it was obtained. One proof may support multiple rows only when its scope covers each file. A receipt must include the relevant asset/terms and should omit unrelated personal, account and payment information. Do not store credentials.

`verified` requires evidence that permits the intended commercial redistribution/use. `placeholder-only` means proof or confirmation is pending; `remove` means the file cannot remain for production. For `own work`, `Proof` may be `-`; verification still requires the owner's/contributor's actual confirmation and date, not an inferred assignment of rights. Retain authorship evidence without upgrading it to a licence claim.

Fonts require SIL OFL 1.1 text shipped beside the font. CC-BY 4.0 needs attribution in credits as well as its proof; NC, ND, SA and personal-use-only sources do not qualify under the binding design guide. AI assets require the owner's explicit approval for that exact asset and evidence of permitted commercial use. Do not generate or import them as part of AST-001.
