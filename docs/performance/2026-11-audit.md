# November 2026 performance investigation

Owner-directed work, 2026-11-06. Lead and two Astra light workers audited the current game after fetching Daniel's published changes. Baseline: `cc19fd5f` (contains `origin/main`); baseline compilation succeeded. No publishing authorized. The pre-existing Unity rewrite of the URP global settings asset is excluded.

**Delivered:** full largest-Hollow blueprint reconstruction **3.16x**, content refresh **2.04x**, integrity selection **5.81–10.90x**, box removal **1.81x**. No whole-game FPS speedup is claimed.

The target is at least 2x improvement without reducing resolution, geometry, shading, MSAA, simulation frequency, collision precision, damage semantics or determinism. Subsystem speedups are reported as subsystem speedups: halving a component that costs 10% of a frame saves only 5% of total frame time. Whole-game FPS is not inferred from microbenchmarks.

## Ranked additional opportunities

These are hypotheses until measured.

1. **Exact ray rejection.** `Simulation/Weapons/CombatHitTest.cs` traverses the whole segment through each candidate; `Voxel/Model/VoxelRaycast.cs` steps individual cells even through absent bricks. Conservative grid-local AABB rejection is safer than immediately changing entry/clipping arithmetic. Preserve shield priority, starts inside, 3D transforms, boundary/tie rules and candidate ordering.
2. **Redundant propulsion solve.** `Simulation/Flight/PropulsionJob.cs` solves both bled and exact warm starts. If the bled residual is already below its improvement threshold, a nonnegative second residual cannot win. Preserve iteration counts, selected floating-point arithmetic and saturated braking behavior; measure flight workload before implementing.
3. **Renderer traversal.** `Voxel/Rendering/BrickPoolRenderSystem.cs` writes every brick matrix; `BrickCullJob.cs` scans full pool capacity and sorts visible index ranges each frame. Cache only provably unchanged data and use conservative bounds. Hidden grids, shadow casters, rebasing, split/reparenting, buffer growth and delayed resource disposal must remain correct. Existing renderer fixtures use 1x MSAA: they cannot establish unchanged-quality game performance at 4x MSAA.
4. **Duplicate save capture.** Fleet/Galaxy participants expand structures to temporary dense source cells, then copy to persistent snapshots. Capture once into owned storage, without weakening snapshot isolation, background ownership or failure cleanup. Existing fake-source capture tests miss the expansion cost.
5. **Blueprint Lab rendering.** DraftRenderer completes previous jobs and repeatedly sorts remaining dirty work; transforms/prop bounds are recalculated for unchanged drafts. Cache derived values with complete invalidation and preserve nearest-first scheduling and edit responsiveness.
6. **Zones/mines/spatial hash.** Per-tick full gathers/sorts and Cartesian scans can dominate hazard-heavy races. Large/diagonal spatial queries enumerate rectangular buckets, deduplicate/sort, or fall back to all proxies. Preserve exact output order, overflow behavior and trigger/impulse semantics.
7. **Damage and collider assembly.** Sparse blasts scan bounding volumes; integrity expands duplicate neighbor nodes; assembling many changed collider children shifts arrays repeatedly. Optimize occupancy/traversal/merge work without changing damage order, island anchors, collider bevels, budgets or install deadlines.
8. **Co-op snapshot serialization.** Serialize identical per-entity snapshot content once per capture and reuse it per peer; avoid overflow rollback allocation. Validate packet bytes and priority resets exactly. World/player command changes invalidate any cache; never persist stale aim state across ticks.
9. **HUD and presentation allocations.** WorldOverlay distance formatting still creates strings before equality checks; every candidate gets repeated projection/component access. Optimize quantized string construction and gather work without reducing update rate or changing rendered labels. Dust is presentation-only but its world-space lattice and rebase behavior must match.
10. **Iteration tooling.** Content membership scans selected first. Preserve native leak checks, compile diagnostics, exact test inventories and project locks. Closed control-sheet polling already sleeps; disabling it is not a new optimization.

## Measurement protocol

- Paired old/new implementation on the same machine, assets and input; alternate order, 60 warmups and 300 measured samples where applicable; record median and p95, not the best run.
- Baseline and optimized outcomes must agree before interpreting speedup. Malformed save acceptance is part of correctness, not optional overhead.
- Whole-game capture uses the production Hollow camera, 4x MSAA and unchanged quality settings. Wait for spawn/mesh/collider readiness, then sample passive profiler recorders without ECS reads or explicit job completion inside the measurement window.
- Take diagnostic snapshots only outside that window: `DevPerfCounters.Format` forces `CompleteAllTrackedJobs` and detailed snapshots scan bricks.
- Include named Burst job handles; the existing `PerfMarkers` pattern misses many job names. Nested or parallel marker times must not be summed into a fictitious frame cost.
- Report GPU timing unavailable when counters/timestamps are absent; zero is not a valid measurement. Record build type, resolution, VSync and frame cap.
- The authored Hollow contains 187 tracked grids (86 pieces, 17 guns, 36 moorings, 44 boulders, four coast wrecks), plus traffic/guards/player and other content. The 92-root microbenchmark is conservative, not an exact live-scene count.

Known unrelated baseline issues remain in HANDOFF-ASTRA.md, including the save restore warning failure and the missing DMG-020 spec definition. `check-docs.py` still reports that pre-existing dependency error; no test threshold is relaxed to hide it.

## Final loading result

PERS-020 + VOX-022 + PERS-021 reconstruct the largest shipped Hollow blueprint with the original geometry and content in **6.2422 ms median versus 19.7534 ms** for the retained original decoder/storage (**3.16x**). p95 improves **38.8033 → 17.2029 ms** (**2.26x**). This is full in-memory VOXS decode + structure reconstruction, excluding disk IO and disposal equally; it is not total scene boot time or whole-game FPS. Workload: `ship_hollow_den_hulk`, 41,908 compressed bytes, 53,199 solid cells, 103 bricks, 5,974 instances. Same asset, same process, 60 warmups and 300 alternating paired samples. Original code remains a differential oracle; no validation was removed.

Final stage medians/p95: codec **13.7477/29.6999 → 4.7927/15.1186 ms**; storage **5.7942/11.9883 → 1.4050/3.0084 ms**. Absolute timings vary between runs, so use paired comparisons rather than combining baselines across runs. Final codec regression: **32 passed / 0 failed / 0 skipped**, including the two new direct-loop cases with Burst enabled and disabled (`Logs/perf-round/codec-final-functional.xml`).

Durable raw performance records and rendered-capture metadata are in [results/2026-11-06](results/2026-11-06/). The two-codec-pass limit is reached for this round. Further loading tuning should use a new integrated bottleneck measurement, rather than chasing the microbenchmark.

Additional tool/configuration coverage: authoring jobs `tools/jobs/GAL-012-import-world.cs` force-import whole content groups; `ENC-010-generate-content.cs` repeats catalog rebuilds. Preserve import/validation boundaries before consolidating them. `tools/controlsheet/sheet.js` polls every 100 ms even when an open browser tab is hidden; visibility-aware polling is a candidate (closed tabs already stop). `tools/iteration-gates.sh` includes CLI setup/evaluation/polling, so its metric represents workflow latency. Audio event draining completes producer access and coalesces synchronously; profile battle-heavy workloads before changing it. Music already streams/loads in background, scene loading is asynchronous, and fast Enter Play Mode is enabled. Production render settings were not reduced.
